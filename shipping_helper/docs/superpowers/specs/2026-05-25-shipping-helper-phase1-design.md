# ShippingHelper Phase 1 设计规格

## 1. 概述与目标

**项目名称：** ShippingHelper - 宏昊船务助手

**阶段目标：** 开发 Phase 1 功能，完成订单数据提取与包装计算，作为船务部日常工作流程的第一阶段。处理结果供船务部同事核对后，进入 Phase 2 的模板填充工作。

**核心价值：** 将原本分散在多个Excel表格和纸质文件中的订单信息，整合为一个清晰的界面操作流，减少重复复制粘贴，提高工作效率。

### 2.2 界面组件说明

**数据输入区（左）：**
- 订单表粘贴文本框：多行文本输入，用于粘贴从在线表格复制的一行数据
- PI文件上传按钮：支持拖拽或点击选择.xls文件
- 开始计算按钮：触发数据解析与计算
- 知识库状态显示：显示已加载的产品信息、客户信息版本

**结果展示区（右）：**
- 合并字段结果：展示从订单表和PI提取合并后的23个字段
- 包装计算结果：展示桶数、卡板数提及体积、毛重
- 每项结果支持点击复制到剪贴板

### 2.3 交互说明

- 用户在左侧输入区粘贴订单表数据，上传PI文件，点击计算
- 系统解析数据，从知识库补全缺失字段，计算包装
- 结果显示在右侧，用户可逐项点击复制
- 确认无误后，点击「进入Phase 2」按钮

## 3. 功能模块设计

### 3.1 核心模块

**OrderParser（订单解析器）**
- 职责：解析Tab分隔或换行分隔的订单表粘贴数据
- 输入：字符串（粘贴的订单表数据）
- 输出：字典（23个字段）
- 特殊处理：智能修复列偏移、合并嵌入换行的订单要求字段

**PIExtractor（PI文件提取器）**
- 职责：从.xls格式的Proforma Invoice提取关键信息
- 输入：.xls文件路径
- 输出：字典（收货人、PI号、品名、数量、单价、金额、H.S.Code、卸货港）
- 依赖：xlrd库

**CodeMatcher（商品编码匹配器）**
- 职责：根据内部编号从知识库匹配商品信息
- 输入：内部编号字符串
- 输出：字典（报关名称、海关编码、报关成分、产品颜色）
- 知识库格式：JSON（见附录）

**PackageCalculator（包装计算器）**
- 职责：根据订单要求和包装规格计算桶数、卡板数提及体积、毛重
- 输入：订单要求文本、总数量（kg）
- 输出：字典（桶数、卡板数提及体积、毛重）
- 支持：不打卡板模式、液体/粉分类处理

**Merger（数据汇聚器）**
- 职责：合并订单表、PI文件、知识库三处数据
- 输入：OrderParser结果、PIExtractor结果、CodeMatcher结果
- 输出：统一的订单记录字典

### 3.2 数据流

```
用户粘贴订单文本 ──┐
                   ├──► OrderParser ──┐
                   │                 │
上传PI文件 ────────┼─────────────────┼──► Merger ──► 结果展示
                   │                 │
内部编号 ──────────┼──► CodeMatcher ─┘
                   │
                   └──► PackageCalculator ──► 包装结果
```

## 6. 异常处理

### 6.1 解析异常

- **订单表为空**：提示用户粘贴数据
- **列偏移**：报关名称位置为纯数字时，自动插入空值
- **嵌入换行**：订单要求字段内含换行时，智能合并
- **PI文件格式错误**：提示检查文件格式是否为.xls

### 6.2 知识库异常

- **内部编号未匹配**：提示用户手动输入报关名称
- **商品信息缺失**：标注为空，等待手动补全

### 6.3 包装计算异常

- **桶类型未找到**：列出可用桶类型供选择
- **订单要求无法解析**：提示手动指定包装方案
